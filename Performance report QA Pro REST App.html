Performance report QA Pro REST App

1. Introduction

Мета - оцінити продуктивність та стабільність системи QA Pro REST App під різними рівнями навантаження: від базового Baseline до Stress/Overload.

2. Тестове середовище

  • ОС: Windows 11
  • CPU: 6 cores @ 3.6 GHz
  • RAM: 32 GB
  • JMeter: 5.6.3
  • Docker: 4.46.0

3. Test scenario

  • Test 1 (Baseline Load): 100 VUs, Ramp-Up 1 s, Loop 1
  • Test 2 (Load Test): 1 000 VUs, Ramp-Up 1 s, Loop 2
  • Test 3 (High-Concurrency Load): 5 000 VUs, Ramp-Up 1 s, Loop 4
  • Test 4 (Short Soak): 1 000 VUs, Ramp-Up 2 s, Loop ∞, Duration 30 s
  • Test 5 (Soak/Endurance): 5 000 VUs, Ramp-Up 3 s, Loop ∞, Duration 60 s
  • Test 6 (Stress/Overload): 10 000 VUs, Ramp-Up 5 s, Loop ∞, Duration 180 s

7. PerfMon correlation with system load

Цей розділ поєднує дані навантажувальних тестів із системними метриками. Порівняння дозволяє виявити моменти деградації та корелювати поведінку сервісу з навантаженням.

Key Observations from the Report

  • Test 1: надто короткий, метрики PerfMon не зафіксовані.
  • Tests 2–3: система стабільна, CPU тримає навантаження, пам’ять не росте.
  • Test 4: пам’ять поступово зростає, CPU трохи знижується → можлива ознака накопичення кешу.
  • Test 5: CPU та RAM досягають піку → початок деградації, хоча помилок ще немає.
  • Test 6: CPU та RAM досягають піку → максимальна деградація, помилки, збій під час навантаження.

8. Summary

  • 1.Baseline (100 VUs): 1 ms, 0% помилок — підтверджена базова працездатність.
  • 2.Load (1 000 VUs): 206 ms, ~2 332 req/s — висока продуктивність.
  • 3.High-Concurrency (5 000 VUs): 794 мс, ~2 947 req/s — масштабованість без помилок.
  • 4.Short Soak (30 s): стабільно ~2 869 req/s, 273 ms — без деградації.
  • 5.Soak (60 s): throughput знижується до ~1772 req/s — перші ознаки ресурсного навантаження.
  • 6.Stress (180 s): error ≈ 3.86 %, avg 1401.86 ms — система входить у зону деградації, збій.

9. Recomendations

  • Оптимізувати запитів: кешування значень, зменшення кількості однотипних звернень до серверу.
  • Налаштувати таймаути (> 5 с) та логування довгих транзакцій.
  • Визначити поріг навантаження, після якого починається деградація (~5K VUs)
  • Затримки до 150 s потребують оптимізації.
